# AGENTS.md

## Dev environment tips
- Install dependencies with `npm install` before running scaffolds.
- Use `npm run dev` for the interactive TypeScript session that powers local experimentation.
- Run `npm run build` to refresh the CommonJS bundle in `dist/` before shipping changes.
- Store generated artefacts in `.context/` so reruns stay deterministic.

## Testing instructions
- Execute `npm run test` to run the Jest suite.
- Append `-- --watch` while iterating on a failing spec.
- Trigger `npm run build && npm run test` before opening a PR to mimic CI.
- Add or update tests alongside any generator or CLI changes.

## PR instructions
- Follow Conventional Commits (for example, `feat(scaffolding): add doc links`).
- Cross-link new scaffolds in `docs/README.md` and `agents/README.md` so future agents can find them.
- Attach sample CLI output or generated markdown when behaviour shifts.
- Confirm the built artefacts in `dist/` match the new source changes.

## General Rules

- Before implementing any change, analyze the full context of the existing code.
- Always reuse existing patterns already present in the project.
- Never introduce a new architecture unnecessarily.
- Never duplicate code.
- Always prioritize readability and maintainability.
- Always explain complex decisions through short comments when necessary.
- Do not change code unrelated to the requested task.

## TypeScript

- Use the most specific type possible.
- Never use `any`.
- Never use `as any`.
- Never use `@ts-ignore`.
- Never use `@ts-expect-error` without justification.
- Never use casts to hide type errors.
- Create explicit interfaces and types for complex structures.
- Prefer inference when the type is already obvious.
- Code must be compatible with `strict: true`.
- Always handle `null` and `undefined` values.
- Prefer union types and discriminated unions when appropriate.

## React

- Components should have a single responsibility.
- Avoid large components.
- Extract complex logic into hooks.
- Avoid unnecessary re-renders.
- Do not use useEffect when a derived solution is possible.
- Do not store in state values that can be derived.

## Next.js

- Use Server Components by default.
- Use Client Components only when necessary.
- Minimize use of "use client".
- Use Server Actions when appropriate.
- Avoid duplicate fetches.
- Respect the App Router architecture.

## TanStack Query

- Use hooks generated by Orval whenever possible.
- Never duplicate existing calls.
- Invalidate cache correctly after mutations.
- Do not use manual fetch if a generated hook already exists.

## API

- Reuse existing schemas.
- Do not create duplicate DTOs.
- Respect existing OpenAPI contracts.
- Never alter contracts without explicit need.

## Prisma

- Use specific selects.
- Never fetch unnecessary columns.
- Avoid N+1 queries.
- Always use transactions when necessary.
- Respect already defined relationships.

## UI

- Use ShadCN components when available.
- Never change ShadCN components directly — they are generated by `npx shadcn-ui` and should only be modified via CLI.
- Maintain visual consistency.
- Do not create custom components if an existing component solves the problem.
- Ensure responsiveness.

## Forms

- Use React Hook Form.
- Use validation with Zod.
- Reuse existing schemas.

## Imports

- Remove unused imports.
- Organize imports automatically.
- Use project aliases.

## Performance

- Avoid unnecessary renders.
- Avoid redundant queries.
- Avoid unnecessary loops.
- Prioritize simplicity over micro-optimizations.

## Security

- Never expose secrets.
- Never trust client data.
- Validate inputs on the backend.
- Sanitize content when necessary.

## Before Finishing

Always verify:

1. Is there similar code that can be reused?
2. Is the typing correct?
3. Is there risk of regression?
4. Does the code follow project patterns?
5. Is the solution the simplest possible?
